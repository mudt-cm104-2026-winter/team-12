# How We Review Pull Requests

## Purpose

We review pull requests to improve our Room Booking application and avoid mistakes before merging changes into main.

## Review Process

1. Open a pull request from another team member.
2. Go to the Files changed tab.
3. Read and understand the changes.
4. Leave at least one comment on a specific line using Start a review.
5. Click Submit review and select a review option.

## Review Options

- Comment: Give feedback or ask a question.
- Approve: The changes are ready to merge.
- Request changes: The author needs to fix something before merging.

## Room Booking Checklist

- Are the changes related to the issue?
- Are the room and booking details clear?
- Is the code easy to understand?
- Is there any unnecessary or repeated code?
- Are passwords and personal data excluded?

## Team Rules

- Do not commit directly to main.
- Every pull request must be linked to an issue.
- At least one team member must approve before merging.
- Nobody can approve their own pull request.
- If changes are requested, the author must fix them before approval.
